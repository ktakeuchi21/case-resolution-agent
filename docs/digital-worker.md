# Persistent digital case worker

This September 2026 increment extends the synthetic public portfolio MVP. The live release identity is recorded in `hosted-verification.md`; implementation alone is not a hosted acceptance claim. All channels, identities, documents and effects are synthetic. The exact completion boundary remains **Documentation dependency resolved; prior authorization pending.**

## Product behavior

Pathway Agent accepts bounded, attested free-form questions, retains multiple conversations, resolves conversational clarification, prepares four audience summaries and five channel drafts, stores edited versions, and records synthetic channel interactions. The operational workflow remains the only authority for task resolutions, package verification, effects, timers and acknowledgment. Conversation does not update canonical case facts. Starting a new conversation preserves earlier conversations, the latest unverified channel interaction, workflow history and immutable evidence.

The primary answer shows the response, next step, owner and permission at answer time. Exact citations expand below it; claims, hashes, full evidence and generation output stay in advanced details. Historical answers are not rewritten after retirement or case changes. The current sidebar is rebuilt from the durable case rather than reusing an old answer’s owner. Unrecognized source questions with unavailable vectors pause explicitly.

The Knowledge Studio accepts bounded TXT, Markdown, PDF and DOCX uploads, retains the original separately, exposes normalized passages and location limits, proposes unknown metadata and allows correction/reprocessing. Source families have a searchable/filterable list and selected detail. Library versions distinguish current, future, expired, superseded, retired, draft, conflicted, quarantined and sandbox states. Roles and impact confirmations precede governance actions.

## Architecture and decisions

`src/agent/contracts.ts`, `compose.ts`, `provider.ts` and `service.ts` separate transport, context, composition and persistence. The provider-neutral synthesis interface returns structured claims and exact supporting quotes. Deterministic validation checks schema, quote identity, eligible passages, evidence integrity and selected authority language. A second, fallible model check reviews entailment. Neither step can grant permission or execute effects. The checked claims also supply wording in model-composed summaries/drafts. SMS remains a generic workspace notification without source details.

The default composer uses deterministic case rules and one reviewed synthesis for the exact three-source SC-01 fact set. It is labeled as such and is not claimed as live model intelligence. Other deterministic source claims remain extractive. Administrative sentiment/intent is a bounded cue classifier with supporting language, confidence and uncertainty; it has no action authority. OpenAI `gpt-4.1-mini-2025-04-14` is the optional synthesis adapter; `text-embedding-3-small` supplies configured fresh vectors. Model context contains authoritative workflow facts and governed passages separately from unverified conversational text.

Migration 009 adds separate conversations and immutable response entries plus durable provider-request reservations. An agent response, its fresh workflow snapshot and its retrieval evidence commit in one application transaction bound to the existing RLS/advisory-lock scope. Interrupted saves roll back together. Provider reservations commit separately because a timeout may already be billable. Exact request replay returns the saved answer and does not regenerate it.

Migrations 010–011 add temporary originals, normalized previews, review history, retrieval results and vector indexes. These `portfolio` tables use the established same-origin application trust boundary, not a new claim of per-row database isolation. Every lookup is qualified by the authenticated session workspace. Original-file download uses an owned upload ID, attachment disposition and no-store caching. Canonical governed records retain the existing database RLS, hash validation and immutable triggers.

Parsers run in a short-lived child with no database/provider credentials, a 128 MB JavaScript heap cap and ten-second deadline. Inputs are at most 1 MB; output is bounded to 64,000 characters, 128 passages and 20 PDF pages. DOCX archive entry count, expansion, uncompressed size, macros, XML entities and external relationships are checked. PDF extraction disables scripting/evaluation, attachment use, external fetching, XFA and WASM. PDF reading order is approximate; scanned files require OCR elsewhere. Heap limits are not a guarantee about all native memory. No patient-data detection guarantee is made by screening or attestation.

Temporary indexing uses `PersistentRetrieval.exploreTemporary` and the existing pipeline with a server-owned registry. Its vectors survive request/reconstruction in an expiring owned cache. No temporary upload enters the canonical tables before publication. Metadata/reprocessing invalidates the temporary index and prior approval. Collection comparisons retain effective/requested mode, exclusions, exact citations and all four independent determinations. A proposed collection is an exploration preview plus explicit governance checks, not an operational release.

Review checks do not establish real payer truth. An explicit synthetic Knowledge Reviewer attests the exact revision, source text, applicability, dates, channel/use, facts and extraction limitations. Publication creates immutable canonical records and reviewer evidence. Assignment is separate. A proposed predecessor links a new upload to an existing source family, while actual supersession remains a separate confirmed action. Publication recovery reuses the existing release after an interrupted application receipt. Source retirement never edits historical answers or evidence.
