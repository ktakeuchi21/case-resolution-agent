# Live request activity

Pathway now displays observed work beneath its name in Chat and Email: searching the selected Knowledge Pack, the actual retrieved passage/document counts, preparing an answer, checking its response format and source references, and any existing bounded format repair. Elapsed time starts immediately. Completed activity collapses above the answer and remains available after reload. This is application activity, not model reasoning text or a claim that every fact has been independently verified.

Each turn has optional activity metadata in its existing session-isolated JSON record. Events contain the turn ID, attempt, sequence, stage, message and elapsed milliseconds. Stage transitions are persisted before being sent through the existing NDJSON response. The existing `message` field remains compatible with the previous frontend. Earlier turns have no fabricated activity history; retries replace the activity for that attempt. Activity and its original Knowledge Pack remain fixed when the selected pack changes.

The browser uses streamed events first, then polls the existing conversation endpoint at most once every three seconds while the stream is silent. It merges missed events without regressing the displayed stage, never submits another generation request for a status check, and stops on completion, navigation or the existing 90-second deadline. Reloading a recent pending turn resumes observation only. Timers update text in place and are not repeatedly announced to screen readers. Disclosure, drawer focus, transcript scroll and composer behavior are preserved.

GPT-5 mini, low reasoning effort, the generation input, retrieval filters, provider request ceilings and bounded repair policy remain unchanged. No model summaries, new endpoint, database migration, external dependency or new hosting resource is introduced. Activity strings are application-owned and rendered as text; existing session isolation, CSRF checks, CSP and rate limits continue to apply.
